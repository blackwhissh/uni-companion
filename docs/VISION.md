## 1. Purpose

Define the problem, intended outcome, scope boundaries, and success criteria for Uni Companion.

## 2. Problem statement

University students often:

- Study from lecture PDFs without structured, course-grounded support.
- Use generic LLM tools that are not tied to official course materials.
- Struggle to find peers for study groups, projects, thesis topics, or language practice.
- Rely on informal channels (WhatsApp, hallway asks) with poor discoverability.

Generic “PDF → chatbot” tools are commodity. They rarely combine **official course knowledge** with **campus-local collaboration**.

## 3. Vision statement

> For students at Universität Siegen (initially), Uni Companion turns **admin/professor-published course materials** into a grounded study system and helps enrolled students discover peers studying the same modules.

## 4. Goals

| ID | Goal |
|---|---|
| G-1 | Ground study tools in canonical, published course materials. |
| G-2 | Reduce time-to-productive study (Q&A, flashcards, quizzes). |
| G-3 | Increase discoverability of compatible study partners on campus. |
| G-4 | Provide a CISS-relevant path: RAG → personalization → matching → agents. |
| G-5 | Use the product as a high-trust networking surface in the university ecosystem. |

## 5. Non-goals (current horizon)

| ID | Non-goal |
|---|---|
| NG-1 | Compete as a generic ChatGPT front-end. |
| NG-2 | Public marketplace for unauthorized lecture redistribution. |
| NG-3 | Student-uploaded canonical course packs as the default model. |
| NG-4 | Multi-university production before Siegen validation. |
| NG-5 | Full LMS replacement (sync later ≠ replace). |
| NG-6 | Positioning as a funded startup before campus evidence. |

## 6. Target users

| Persona | Needs |
|---|---|
| Student (primary) | Study on official materials; find peers |
| Course Admin / Professor | Publish materials; control visibility |
| Fachschaft / operator (later) | Help run courses; campus coordination |
| Project owner (Phase A) | Acts as Course Admin for the pilot course |

## 7. Value proposition

| For | Value |
|---|---|
| Students | Grounded study + easier peer finding |
| Faculty / admins | Controlled material publishing |
| Project / thesis | Progressive intelligent-systems architecture |

**Defensibility:** summarization is commodity; **institution-scoped published knowledge + personalization + matching** is not.

## 8. Success criteria

| Horizon | Criterion |
|---|---|
| Phase A | S-0 + S-1 demo; publish/unpublish enforced; ≤ 5 min student path |
| Phase A+ | ≥ 5–10 classmates on one course |
| Phase B | Real professor/Fachschaft admin; matching requests used |
| Research | Documented RAG + at least one advanced component later |

## 9. Strategic framing

Framed as a **student-built research/technology project** at Universität Siegen. Commercial packaging is deferred.
